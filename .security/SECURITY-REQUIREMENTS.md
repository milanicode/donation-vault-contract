# Security Requirements — <project name>

> Requirements live machine-readably in `.security/threat-model.yaml`
> (`requirements:`). This document explains and refines them for humans.

A good security requirement is:

- **Testable** — it can fail. "Be secure" is not a requirement;
  "only the owner can pause" is.
- **Traceable** — it names the threats (THR-*) it mitigates.
- **Realizable** — it can be expressed as one or more invariants (INV-*)
  and ultimately as tests.
